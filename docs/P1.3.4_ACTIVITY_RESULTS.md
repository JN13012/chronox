## Bilan fonctionnel

- Deux mesures distinctes : session V2 et activité clavier/souris.
- Détection activée/5 min par défaut ; 1/5/10/15/30 min disponibles.
- Grâce comptée, coupure à l'échéance indépendamment du retard du polling,
  reprise prospective après entrée valide.
- Mode désactivé explicite, suivant la session uniquement après le changement.
- Aucun contenu, hook, exemption applicative ou reconstitution historique.
- Doutes d'entrée et de puissance signalés, avec conservation du temps certain.
- Stockage V3 additif, checkpoints atomiques, récupération durable uniquement.

  dans sa structure, sans refonte du widget.

activité réellement nulle d'une période sans mesure, notamment sous verrouillage.
Elle n'ajoute aucune durée aux compteurs.

## Performances

Le probe natif compare les bibliothèques de production V2/V3 dans des processus
isolés : 1 Hz, appels Windows réels pour V3, trois requêtes de périodes comme le
widget, checkpoint à soixante secondes, bases temporaires uniquement. Les
mesures CPU sont celles du processus et sont exprimées en pourcentage d'un cœur.
La RAM indiquée est la mémoire privée du probe, pas celle de l'application UI.

Les premières répétitions de développement donnent V2 entre 0 et 0,286 % d'un
cœur, V3 entre 0,078 et 0,573 %, avec 68 handles stables dans les répétitions
comparables. Une première exécution V2 avait 74 handles, également stables.
Les maxima de mémoire privée restent entre 1,21 et 1,33 Mio pour ces relevés.

Ces mesures courtes sont sensibles à la quantification CPU et à la variabilité
entre processus. Elles ne prouvent ni une différence exacte de quelques Ko,
ni l'absence de fuite à long terme. L'initialisation des ressources UI n'est
pas incluse dans le probe. Le coût complet de l'application candidate sur un
profil isolé prolongé reste **NON TESTÉ** ; aucune mesure du moteur installé
V2 n'est présentée comme une mesure du candidat V3.

Les résultats du probe compilé avec la livraison finale sont consignés ci-dessous.

| Relevé final, 60 s par processus | V2 | V3 |
|---|---:|---:|
| CPU, % d'un cœur | 0.078106 | 0.078106 |
| Mémoire privée maximale, octets | 1277952 | 1335296 |
| Working set maximal, octets | 6713344 | 6754304 |
| Handles min/max/fin | 68 / 68 / 68 | 68 / 68 / 68 |

Différence privée observée : **+56 Kio** ; différence handles : **0**.
La différence CPU est sous la résolution utile de ces relevés, donc aucun
surcoût CPU précis n'est déductible. Le probe V3 était actif pendant ce relevé ;
il mesure une boucle au repos entre les polls, pas une absence physique
contrôlée d'interactions. Les relevés de développement comprennent également
un passage inactif (activité nulle), sans en faire une mesure du candidat final.

Dans le test de dashboard séparé, les vingt cycles conservent exactement
**1 036 handles, 14 GDI et 22 USER** après initialisation. Cette mesure de
stabilité ne s'additionne pas aux ressources du probe sans UI.

Traces : `build/activity-audit/resources-*-delivery.json`,
`resources-summary.json` et `ctest.xml`.
